# Atlas 2.0 Foundation

## Логіка пошуку Atlas 2.5

1. Atlas розкладає задачу на 1–4 необхідні ланки.
2. Кожна ланка спочатку шукається у реальних Паспортах можливостей.
3. Якщо точного Паспортного збігу немає, Atlas автоматично запускає зовнішній пошук без додаткового кліку.
4. Для товарних запитів Atlas перевіряє конкретні сторінки та готує прямі пошуки у відомих джерелах: ATB, Сільпо, METRO, NOVUS, Auchan, Rozetka, OLX, Prom.ua, Flagma та Google Maps; для оптових агрозапитів також Agro-Ukraine, Agrotorg і Agrotender.
5. Конкретні знайдені товари й оголошення мають пріоритет. Якщо джерело тимчасово не повернуло конкретну картку, Atlas усе одно показує готову дію пошуку в цьому джерелі замість порожнього результату.
6. Користувач може змінити область пошуку вручну: `Поруч`, `В інтернеті` або `Поруч + інтернет`.
7. Atlas не вигадує людей, компанії, ціни або посилання: неперевірені дії чітко відрізняються від конкретних знайдених пропозицій.

## Паспорт потреб

Перший пілот підтримує групу `Овочі`, товар `Томати`, кількість у кілограмах,
період актуальності та статус `Отримано / Не отримано`. Перед запуском виконайте
`supabase-needs-v1.sql` у Supabase SQL Editor.

Після цього виконайте `supabase-needs-catalog-v2.sql`. Він додає керований довідник
груп і товарів та захищену сторінку `/admin/catalog`. Змінювати каталог може лише
підтверджений адміністраторський email; користувачі бачать каталог тільки для вибору.
Файл `supabase-needs-catalog-v2-rls.sql` посилює правило для проєктів, де дозволені
анонімні сесії: вони не отримують права змінювати каталог.

## Запуск
```powershell
npm install
npm run dev
```

## Новий GitHub-репозиторій
Створіть порожній репозиторій `atlas-core`, потім:

```powershell
git init
git add .
git commit -m "Atlas 2.0 Foundation"
git branch -M main
git remote add origin https://github.com/VasylZalesskiy/atlas-core.git
git push -u origin main
```
